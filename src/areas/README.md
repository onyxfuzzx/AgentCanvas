# Managed task areas

Open **Task areas & Git** in the desktop sidebar. Stop terminals, then supply an existing repository root and full base commit ID. Creation checks out only that commit into a new `agentcanvas/<UUID>` branch at `<workspace>/task-areas/<UUID>`. Dirty source edits stay in the source directory. Bootstrap file/script allowlists are empty; install dependencies or configure local tools explicitly in each checkout.

Open an area's canvas scope and launch an agent there. Scope changes hide other nodes without stopping their processes; the full canvas restores all nodes. Area IDs and world-coordinate layouts survive workspace saves. In Tasks, bind a draft's execution area and assign its terminal. Dispatch verifies the terminal's actual native launch directory and refuses another active or unreconciled task in the same checkout. Unmanaged terminals are labeled shared-directory execution.

Stop terminals before review mutations. Read bounded status, file lists, diffs, commit trail and UTF-8 files. Record check results and reviewer findings against the displayed commit. These are explicit user records; the app does not run test commands. Every declared check must pass at the clean current commit before approving a merge preview. The target must be the source repository's currently checked-out branch. Check out another target explicitly outside this workflow if needed. Preview detects conflicts; approval binds both exact commit IDs and the resulting merge tree. Integration revalidates them immediately before a local merge. Git hooks, signing, textconv, external diff and fsmonitor are disabled for managed operations. Repositories with custom checkout filters or merge drivers require manual Git operations. Ordinary system/user EOL settings are preserved; global filters are not loaded or hydrated. Preview also refuses replacing ignored target content. There is no fetch, push, bootstrap script execution or automatic coordinator.

Creation, integration and cleanup write intent to a versioned atomic journal before invoking Git. Interrupted/uncertain operations are never replayed. Inspect paths, branches and target history, finish/abort any in-progress merge manually, then reconcile. A missing, unregistered checkout can be marked removed without deleting anything. Recovered backups require reconciliation; invalid schemas are preserved unchanged. Corrupt originals are archived. Branches are retained after cleanup. Cleanup refuses changed, untracked, ignored, unintegrated, locked or incorrectly registered worktrees and app-owned active writers. External programs are outside the app's authority; stop those writers too. Git worktrees provide code isolation, not an OS security sandbox.

Limits: 128 areas and declared checks per area, managed checkout paths at most 230 UTF-16 units on Windows (refused before branch creation), 2 MiB catalog, 1 MiB per Git output stream, 256 KiB UTF-8 file preview and 30 seconds per Git subprocess. Large changes are refused rather than silently truncated. Limits do not trigger automatic deletion. Integration creates local commits as `AgentCanvas <agentcanvas@localhost>` and preserves source commits. Terminals, task mutations and Git operations are separate from undoable layout history. Normal close/switch waits for pending mutations.
