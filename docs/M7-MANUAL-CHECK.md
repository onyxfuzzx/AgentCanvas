# M7 desktop and release acceptance

Use a disposable workspace for UI checks. The user confirmed the basic activity summary and Light/Dark theme switching in the optimized ZIP build on 2026-11-13; deeper checks below remain pending. Record executed results in VERIFICATION.md. Automated tests and package inspection do not establish installation/upgrade correctness.

1. Launch the optimized portable app with both helper executables beside it. Create a terminal, select it and confirm the activity summary updates from output activity to quiet after five seconds without traffic. Quiet does not assert task completion. When a shell/agent displays a confirmation prompt, check that the summary says **Possible input prompt**. Input should clear stale prompt evidence. Change to a manual label, then back to Automatic. Close/restart the terminal and confirm transient activity/output is not restored.
2. Choose Light, Dark and System in the sidebar. Check text, focus outlines, dialogs, notes, whiteboard, links, browser controls and terminal footer at each setting. Relaunch and confirm the theme preference remains. Test Windows high contrast/reduced motion and a screen reader separately; no assistive-technology certification is claimed.
3. Navigate using Tab/Shift+Tab. Opening New terminal, Manage workspaces or Help should focus a control inside the dialog, keep Tab within it, and return focus when closed. Escape should close a dismissible dialog. Check that a failed save's dialog preserves access to Keep working and Retry. Do not discard real unsaved work as a test.
4. Focus a node header with Tab. Use arrows to move it; use Alt+arrows to resize; hold Shift for 24-unit steps. Undo/redo the changes. Test a multi-selection and an attached whiteboard connector. Shell input and text fields must retain their own arrow keys. Test at 25%, 100% and 200% zoom.
5. Repeat the outstanding M6 overlap, dialog, off-screen, restoration and mixed-DPI checks after the browser scheduling change. With several terminals and browser nodes, pan/zoom and type; observe responsiveness. Measure twenty-agent UI throughput separately before making any frame-rate claim.
6. On a clean Windows 10/11 test machine with WebView2 Evergreen installed, test each installer separately: install, launch from the installed shortcut, start a terminal and verify the helper is available. Check the app and both helpers reside together. Upgrade over the prior build, then uninstall. Confirm workspaces/notes outside the installation directory survive. Test reinstall and a path containing spaces/non-ASCII characters. Do not replace an existing production installation for this check.
7. Extract the portable ZIP to a fresh folder, verify its SHA256SUMS.txt/manifest.json, and run it with WebView2 installed. Confirm startup, helper discovery and normal shutdown. Packages are unsigned; signing and reputation/distribution acceptance are separate release steps.
